# Assumptions: what is real vs simulated

This repo is built to run end to end from a clean clone. Some parts are exercised
locally and in CI; some parts are validated rather than stood up against live
infrastructure. This page is explicit about which is which.

## Real

- **The backend API and the store.** The HTTP/JSON service, the concurrency-safe
  store with maintained indexes, the incident derivation, and the resolve flow all
  run and are covered by Go tests (`go test -race ./...`).
- **The profiling numbers.** The before/after figures in docs/profiling.md are
  measured by committed benchmarks and the real `ng build` output, regenerated by
  `scripts/profile.sh`. Nothing in the metrics table is hand-written.
- **The frontend.** The Angular SPA builds (`npm run build`) and its unit tests run
  (`npm run test:ci`, headless Chrome). It renders real data from the backend.
- **The broker integration.** The `franz-go` consumer and producer are real Kafka
  client code. `docker compose up` brings up Redpanda, streams the fixture through
  it, and the backend consumes live. This path needs Docker, so it is a local/demo
  path, not a CI assertion.
- **Terraform.** `deploy/terraform` is real configuration that `terraform validate`
  and `terraform fmt -check` pass clean, run in CI.

## Simulated

- **The telemetry.** There is no physical constellation. Frames come from a seeded
  synthesiser (`telemetry.GenerateFixture`); a few satellites are deliberately
  steered into fault regimes so the incident feed is non-empty. The injected
  labels are illustrative, not ground truth from a real spacecraft.
- **The anomaly detector** is a small set of rule-based thresholds, chosen to be
  legible rather than tuned. It mirrors the suite's severity thresholds; it is not
  a trained model (that lives in the sibling `groundstation` repo).
- **The SPA fixture fallback** is a representative subset used only when the
  backend is unreachable, so the static SPA still renders.

## CI-verified, not local

- **The Bazel build.** Bazel is not installed in the local dev environment, so the
  local build path is `go build/test`. The `BUILD.bazel` / `MODULE.bazel` files are
  built in CI via `bazelisk` (`.github/workflows/bazel.yml`). The Bazel and Go
  paths compile the same packages.

## Not done

- **No live cloud or cluster apply.** Like the sibling `liftoff`, the Terraform is
  validated, not applied. There is no real Grafana, no real Kubernetes cluster, and
  no cloud spend in this repo. Standing the artifacts up is the operator's call.
- **No metrics exporter wired yet.** The Grafana dashboard and alert rules query
  `console_requests_total` / `console_request_duration_seconds` / etc. The handler
  logs latency today; exposing a Prometheus endpoint with those series is the next
  step and is called out so the dashboards are honest about their inputs.
